# U64x32 Encoding

For publishers encoding prices into `CompressedOracleV1` slot words and for readers decoding
them; read [the slot structure](slot-structure.md) first.

`U64x32` is a compact **binary** pseudo-floating number format for the prices in compressed
oracle slots. It packs a non-negative integer into 32 bits: a 27-bit mantissa and a 5-bit
exponent.

## Layout

```text
bits 31 … 27 : exponent (5 bits)
bits 26 …  0 : mantissa (27 bits)
```

- Mantissa ∈ `[0, 2^27 - 1]`.
- Exponent ∈ `[0, 31]`.
- Decoded value: `value = mantissa << exponent`.

Maximum representable value is `(2^27 - 1) << 31`.

## Encoding Strategy

The contracts include only a decoder; encoding happens off-chain.

When encoding an integer price off-chain:

1. Choose `exponent` so that `mantissa = value >> exponent` fits into 27 bits.
2. Pack `packed = (exponent << 27) | mantissa`.
3. The bits shifted out are lost: the packed word decodes to `value` rounded down to a multiple
   of `2^exponent`.

## Typical Error Bounds

- Precision is best for smaller exponents; larger exponents trade precision for range.

## Usage

- `U64x32.decode(uint32)` — expands the stored 32-bit word to a 64-bit integer,
  `mantissa << exponent` (exact; precision is lost only when a value is encoded).

The oracle stores the `U64x32` word; the decoded value is the E8 mid that `price()` returns.
